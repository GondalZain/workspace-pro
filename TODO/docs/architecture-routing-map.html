Routing roadmap: browser startup → Angular routes → API → MySQL
Tangent Technologies workspace · Generated reference

1. System overview

The app is split into three layers. The Angular SPA (port 4200) handles UI routing and state. The Express API (port 3000, prefix /api) validates JWT and permissions. MySQL stores users, roles, projects, tasks, and notes.

┌─────────────────┐ HTTP + JWT ┌─────────────────┐ SQL ┌──────────────┐ │ Browser (SPA) │ ──────────────────► │ Express API │ ───────────► │ MySQL │ │ Angular 21 │ localhost:3000/api │ Node.js │ mysql2 │ todo DB │ │ localhost:4200 │ ◄────────────────── │ modules/ │ ◄─────────── │ migrations │ └─────────────────┘ JSON responses └─────────────────┘ └──────────────┘

2. Frontend bootstrap

  1. src/main.ts → bootstrapApplication(RootComponent, appConfig)
  2. app.config.ts registers router, HttpClient, and authInterceptor (adds Authorization: Bearer <token> from localStorage).
  3. RootComponent is only <router-outlet /> — all screens are routed children.
  4. API base URL comes from public/env.js → window.__env.API_BASE_URL (default http://localhost:3000/api).

4. Route guards (who may enter)

Request URL │ ▼ ┌───────────────┐ no token/user ┌────────┐ │ authGuard │ ────────────────────► │ /login │ └───────┬───────┘ └────────┘ │ OK ▼ ┌───────────────────┐ has users.manage ┌────────┐ │ dashboardGuard │ ──────────────────► │ /admin │ (admins skip workspace) │ (workspace only) │ └────────┘ └─────────┬─────────┘ │ regular user ▼ Workspace page loads adminGuard: inverse — only users.manage may enter /admin/*

Task detail/edit: taskContextGuard / taskEditContextGuard require TaskStoreService.activeTaskId (session). Legacy URLs with :id redirect: store id → canonical URL without id.

5. Example: open task list → view task

User clicks task → setActiveTaskId + navigate /dashboard/task → TaskDetailPage reads store → TaskStore.refresh() if needed

Data already loaded via GET /api/tasks on dashboard; detail resolves task from in-memory signal array by id.

7. Backend request pipeline

HTTP Request │ ▼ Express app (src/app.js) │ cors, json body, /uploads static ▼ Route mount: /api/auth → auth.routes (mixed public + requireAuth) /api/projects → requireAuth → project.routes /api/tasks → requireAuth → task.routes (+ nested notes) │ ▼ Middleware: requireAuth (JWT verify → request.user.sub) requirePermission('tasks.read' | …) → DB lookup permissions │ ▼ Controller → Service → Repository → mysql2 pool.query / execute │ ▼ JSON response (or error handler)

Server entry: backend/server.js starts HTTP listener and runs initializeDatabase() (create DB, run SQL migrations, seed default admin).

8. Database (MySQL)

Migrations live in backend/migrations/*.sql and are applied in filename order; applied names tracked in schema_migrations.

9. End-to-end example: save a new task

1. User on /dashboard/tasks/new fills TaskEditor → submit 2. TaskEditPage → TaskStore.add(NewTask) 3. TaskApiService POST http://localhost:3000/api/tasks (+ Bearer token) 4. auth.middleware requireAuth + requirePermission('tasks.create') 5. task.controller → task.service → task.repository INSERT INTO tasks … 6. MySQL commits row; API returns Task JSON 7. TaskStore merges into tasks signal; router navigates back (list/kanban/etc.)

10. Configuration checklist

  • Frontend: npm start in TODO/ · env in public/env.js
  • Backend: npm run dev in backend/ · .env for DATABASE_URL, JWT_SECRET
  • DB: npm run migrate in backend (or auto on server start via initializeDatabase)
